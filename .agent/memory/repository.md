# Repository and task rules

- Follow AGENTS.md. Write no code comments. Use readable identifiers and direct technical language.
- Maintain .agent/STATUS.md as a symlink into .agent/worklog/.
- Create small local commits. Never push.
- Use git -c safe.directory=/home/claude/legendary-octo-spork for repository commands if ownership checks require it.
- No Git user identity exists in repository or global config. Use per-command author settings for commits if necessary.
- Some loose-object directories belong to UID 1000 and reject writes from UID 1001. .agent/tools/commit_pack.py publishes normal Git packs through a temporary object store and index, without changing permissions. It works only on perf branches and excludes README.
- The product ships as a text file processor. TCP is a documentation example of future use, with no TCP tests or socket-specific requirements. Preserve ordinary file I/O checks.
- The public library exports process_csv and write_clients. Engine, errors, and monetary types use the public engine, error, and types modules after the user's 99c0a27 API cleanup. Input and output use standard blocking Read and Write traits. The user requested removal of the iterator-based process_txs API.
- The private CSV processing function uses the name process_txs after the user requested renaming read_clients. Do not export it as a replacement iterator API.
- process_csv uses a direct read_byte_record loop with one reusable byte record and borrowed amount text. The user requested removal of the CsvTransactions wrapper. Flush diagnostics before propagating CSV errors and before account output.
- CSV input uses type,client,tx,amount. The transaction column is tx.
- Account output order is unspecified after the user's b3657dc optimization. Compare CSV headers and complete record lists without row order in tests and benchmarks. Preserve duplicate counts and exact amount formatting; validation sorting must run outside benchmark timing.
- CSV test fixtures use aligned multiline tables. Expected account tables include headers, and malformed cases have descriptions. Preserve field counts, trailing newlines, and diagnostic line positions when reformatting fixtures.
- Control records use the deposit ID and full deposit amount. They can omit a trailing amount field; the parser ignores any control amount.
- Only deposits create accounts and history entries. Withdrawals on missing accounts return InsufficientFunds. The engine assumes unique deposit IDs and performs no duplicate ID validation.
- ClientInfo derives Default and contains pub(crate) total, on_hold, and lock fields. It has no methods or duplicate client ID. The engine checks balance calculations before direct field assignments; CSV output uses map keys and calculates available funds from total minus on_hold.
- perf/chargeback-records removes the deposit that completes a chargeback and checks account locks before control history lookup. perf/client-deposit-index adds a Vec<TxId> to ClientInfo and removes every client deposit with mem::take when the account locks. Both variants preserve aggregate on_hold funds and other clients' histories. Master remains unchanged; current experimental source uses the index.
- Amounts use Money(i64) and exact four-place integer arithmetic. Money derives Default with value zero. Money::checked_add and checked_sub accept Money and return Option<Money>, with None on overflow. Use them for balance calculations and account output; access the inner value only within Money's implementation. The user requested removal of generic money values. Preserve generic input and output streams.
- Pipeline functions return anyhow::Result and use the Error enum from src/error.rs as typed operation context. Downcast to Error or MoneyError without parsing messages. Format errors with {error:#} for the complete cause chain. MoneyError and TransactionError remain typed. CSV I/O errors contain io::Error in csv::ErrorKind::Io rather than exposing it through source().
- Tests cover CLI behavior, domain state transitions, amount limits, checked arithmetic, read interruptions, and read/write/flush errors. Both experiment branches pass 5 unit tests and 28 integration tests in debug/release, including history removal and locked-account rejection after removal.
- The user requested removing redundant tests. Avoid repeated stream smoke tests, bulk arithmetic checks that duplicate CLI and benchmark coverage, and tests of library I/O behavior. Retain tests of transaction rules, boundaries, retry logic, and error propagation.
- benches/throughput.rs uses Criterion 0.8.2 as a development dependency. It validates complete CSV output and empty diagnostics before measurement. Criterion times the complete pipeline including cleanup, with a three-second warmup, 30 samples, and a ten-second measurement target. TX_BENCH_ROWS controls input size; Criterion arguments control sampling. Task measurements exist in .agent/worklog/benchmark.json and .agent/worklog/throughput.json.
- Chargeback comparison uses .agent/tools/measure_chargebacks.py and .agent/worklog/chargeback-index.json. It runs exact 1M/10M/100M mixed CLI operations with 1,024 clients for EOF, half-closing, and all-closing patterns. Use child VmHWM sampling rather than wait4 resource peaks, which can include inherited parent memory. Index savings depend on history removal timing; EOF adds overhead, while early account closure permits reuse of table storage. README receives an append only and must remain uncommitted for this task.
- README.md documents API examples, transaction behavior, memory growth, benchmark results, and commands.
